# Как работает система

**Что это.** Система для учёта строительных объектов и работ на них. В ней два вида сотрудников. Постановщик создаёт объекты и задачи, назначает ответственных и принимает работу. Исполнитель выполняет свои задачи и отправляет их на проверку.

**Как движется задача.** Постановщик создаёт задачу и назначает исполнителя. Исполнитель берёт её в работу, затем отправляет на проверку. Постановщик либо принимает работу, либо возвращает на доработку, и тогда обязательно пишет, что исправить. Перескочить через этап нельзя. На карточке задачи каждый видит только те кнопки, которые ему сейчас доступны.

**История.** Каждая смена этапа записывается автоматически: кто, когда, с какого этапа на какой и с каким комментарием. Изменить или стереть эти записи не могут ни постановщик, ни исполнитель. Если задачу удалить, она исчезает из всех списков, и её история тоже перестаёт быть видна. Сами записи остаются в базе данных, но через программу их не увидит никто.

**Как защищены данные.** Правила заложены в саму базу данных, а не только в экраны программы. Поэтому они действуют, даже если кто-то попытается обратиться к данным в обход программы. Без входа в систему не видно ничего. Самостоятельно зарегистрироваться нельзя: учётные записи создаёт администратор. Сотрудник не может сам изменить свою роль.

**Что не может исполнитель:**

- видеть чужие задачи, их историю и объекты, где у него нет задач;
- менять или удалять задачи, даже свои: он может только продвигать свою задачу по этапам;
- принимать работу или перепрыгивать через этап;
- создавать и менять объекты;
- назначить себя постановщиком.

**Как это проверено.** Вместе с системой идёт автоматическая проверка, которая пробует совершить эти запрещённые действия напрямую, в обход экранов. Результаты приведены в README.

**Смена исполнителя.** Постановщик может сменить исполнителя в любой момент, этап задачи при этом не меняется. Прежний исполнитель сразу теряет доступ к задаче, новый видит её вместе с историей.

**Что осознанно упрощено.** Смена исполнителя не отражается в истории: история фиксирует только смену этапов. Удалённую задачу нельзя восстановить через программу. Эти и другие решения описаны в `docs/DECISIONS.md`.
